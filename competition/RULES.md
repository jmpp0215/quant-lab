# 저PBR 바구니 종목 고르기 경연 — 룰북

이 룰북은 사전 등록 문서입니다(research/pbr.md §78). **누구든 public이나 private 점수를 보기 전에 커밋**하고,
이후 바꾸는 것은 맨 아래 "변경 기록"에 날짜와 이유를 남깁니다. 숨긴 구간 점수를 본 뒤 그 점수를 바꾸는 쪽으로
규칙을 고치는 것은 금지입니다.

## 1. 질문

> 저PBR Top 50 바구니 안에서, **그 시점에 알 수 있는 정보로** 이후 20거래일 동안 더 오를 종목을 가려낼 수 있는가?

지표는 자유입니다. 5·20·60일 수익률, 이동평균, 52주 고가·저가, 거래대금, 배당, 외부 데이터 등 무엇이든 됩니다.
지금까지 이 바구니에서 기각된 것들(research/pbr.md §12 추세 결합, §52 하락 추세 제외, §55 단기 부진 정리, §70 12-1 모멘텀)도
다시 시도할 수 있습니다. 다만 같은 실패가 반복될 가능성이 높다는 점은 알고 시작하세요.

## 3. 참가 등록

**이 맥북에서 작업하는 사람과 에이전트 (기본):**

```bash
source .venv/bin/activate
python competition/register.py <id>        # 예: jongmin, claude, codex
```

`competition/participants/<id>/`가 만들어지고 리더보드 참가자 표에 한 줄이 붙습니다.
에이전트마다 다른 id를 씁니다. 에이전트에게 맡길 때 줄 지시문은 §12에 있습니다.

**레포 밖 참가자:**

1. 호스트에게 `quant-comp-public.zip`을 받습니다. 호스트는 `python competition/prepare_data.py`로 이 파일을
   만들고 `competition/data/dist/`에서 꺼내 전달합니다. 안에 있는 것: 룰북, 채점 코드, 템플릿, 기준선, train 데이터.
2. 압축을 풀고 Python 3.11 이상과 `pip install pandas numpy`를 준비한 뒤 `python competition/register.py <id>`를 실행합니다.
3. 작업한 뒤 `participants/<id>/` 폴더 전체를 압축해 호스트에게 보냅니다.
   호스트는 그 폴더를 레포의 같은 위치에 넣고 채점합니다. public 제출을 원할 때도, 마감 전 최종 제출 때도 같은 방법입니다.

id는 영문 소문자·숫자·`-`·`_`, 2~20자입니다. 한 사람이 id 하나만 씁니다(여러 id로 public 제출 한도를 늘리는 것은 금지).

## 4. 데이터

**격자.** KRX가 날짜별로 낸 KOSPI 전 종목 스냅샷이 10거래일 간격으로 있습니다. 2005-09-01부터 2026-10-14까지
스냅샷 522개, 상장폐지 종목이 들어 있어 생존 편향이 없습니다. 일별 데이터가 아니라서 "5일 수익률"이나
"20일선"은 이 격자로 근사하거나 외부 데이터(§8)로 직접 만들어야 합니다.

**구간.**

| 구간 | 결정일 | 결정일 수 | 공개 여부 |
|---|---|---|---|
| train | 2006-09 ~ 2013-11 (라벨이 2013-12-31 안에서 끝남) | 91 | 모두에게 공개 (`data/public/`) |
| public | 2014-01 ~ 2016-12 | 36 | 숨김. 각자 채점, 점수 한 숫자만 보임 |
| private | 2017-01 ~ 2026-09 | 119 | 숨김. 마감 후 한 번만 채점 |

**`data/public/train.csv.gz` 열** (한 행 = 한 스냅샷의 한 종목):

| 열 | 뜻 |
|---|---|
| `date`, `snap` | 스냅샷 날짜, 스냅샷 번호(0부터, 모든 구간에서 같은 번호) |
| `code` | 종목코드 6자리 (우선주 포함) |
| `close`, `mktcap`, `volume`, `value`, `shares` | 종가(원주가, 수정 안 됨), 시가총액, 거래량, 거래대금, 상장주식수 |
| `bps`, `per`, `pbr_krx`, `eps`, `div`, `dps` | KRX 펀더멘털. BPS는 공시 후 반영돼 미래 정보가 없음. 0이나 빈칸은 값 없음 |
| `ret` | 직전 스냅샷 대비 보유자 수익률. 분할·병합·감자는 시가총액 비율, 신주 발행은 주가 비율 (research/pbr.md §70 규칙) |
| `gap` | 직전 출현 스냅샷과의 칸 수. 1이면 연속, 빈칸이면 첫 출현 |
| `fund_filled` | 2008-08-14 ~ 2008-11-25 스냅샷 8개는 KRX가 BPS·EPS를 모두 0으로 줌. 직전 실제 값을 이어 붙였다는 표시(늦은 값이지 미래 값은 아님). 이 날짜의 `per`·`pbr_krx`·`div`는 빈칸 |
| `suspect` | `ret`이 +100% 초과 또는 −50% 미만. 대부분 KRX 데이터 오류(병합 뒤 주식 수가 한 칸 늦게 바뀜, 잘못된 종가)이고 일부는 진짜(우선주 급등). 약 0.18% |

`data/public/kospi_train.csv`에는 KOSPI 지수의 일별 종가·등락률·PER·PBR·배당수익률이 있습니다.

**알려진 한계.** 배당이 수익률에 들어가지 않습니다. 2019-11 → 2019-12 사이는 출처가 바뀌어 간격이 6일로 짧은 칸이 하나 있습니다.
관리종목 여부와 업종 정보는 없습니다.

## 5. 과제

결정일 t마다(2스냅샷, 약 20거래일 간격, 겹치지 않음):

- **유니버스**: t 스냅샷에서 BPS > 0, 종가 > 0, 거래량 > 0인 종목 중 종가/BPS가 낮은 50개입니다.
  실전 토스 PBR 규칙을 단순화한 것입니다(§36과 같음).
- **라벨**: t부터 t+2 스냅샷까지 보유자 수익률(`ret`을 곱한 값). 중간에 사라진 종목은 마지막 가격을 회수한 것으로 봅니다
  (이후 0%). 창 안에 `suspect` 칸이 있는 종목은 그날 채점에서 뺍니다.
- **제출물**: `predict()` 함수 하나가 든 `.py` 파일입니다. 템플릿은 `participants/_template/submission.py`입니다.

```python
def predict(hist, universe, as_of, kospi, ext_dir) -> pandas.Series:
    # hist: t까지의 전체 패널 (미래 행은 아예 없음) / universe: 종목코드 50개 / as_of: t 날짜
    # kospi: as_of까지 지수 / ext_dir: 내 폴더의 external/
    # 돌려줄 것: 종목코드 -> 점수 (높을수록 더 오를 것)
```

빠진 종목이나 NaN은 중간값으로 채웁니다. 모든 점수가 같으면 "정보 없음"으로 IC 0이 됩니다.
**결과는 결정적이어야 합니다.** 난수를 쓰면 시드를 고정하세요. 한 결정일 계산은 1분 안에 끝나야 합니다.

## 6. 채점

결정일마다 유니버스 안에서 잽니다.

- **IC (주 점수)**: 점수 순위와 라벨 순위의 상관(Spearman)입니다. 결정일별 IC를 평균합니다. 결정일이 겹치지 않으니 t값은 평균 ÷ (표준편차/√n)입니다.
- **증분 IC**: 내 점수 순위에서 기준선(60일 반전, `participants/baseline/`) 순위로 설명되는 부분을 뺀 나머지의 IC입니다.
  기존 연구가 이미 찾은 "빠진 종목이 반등한다"를 다시 찾은 것인지, 새 정보인지를 가릅니다.
- **상위 절반 초과수익**: 점수 상위 절반의 평균 라벨에서 50개 전체 평균을 뺀 값에 12.5를 곱한 연 %p입니다. 비용 제외, 참고용입니다.
- **지연 점검 (private만)**: hist를 한 스냅샷(약 10거래일) 늦게 주고 다시 잰 IC입니다.
  같은 날 종가로 신호를 만들고 같은 종가에 산다고 가정한 효과(호가 반등 등)에 기대는 신호를 걸러냅니다.

**판정 (private 기준, 사전 고정):**

| 판정 | 조건 |
|---|---|
| 통과 | private IC > 0, t ≥ 2, 지연 점검 IC > 0 |
| 새 정보 | 통과 + 증분 IC > 0, 증분 t ≥ 2 |
| 미통과 | 그 밖 |

**순위**는 private 평균 IC로 매깁니다. 같으면 증분 IC로 가립니다. train·public 점수는 순위에 들어가지 않습니다.

참고로 기준선 자체의 train 점수는 리더보드 첫 줄 아래 "기준선" 문단에 있습니다.

## 7. 제출

| 종류 | 누가 | 횟수 | 보이는 것 |
|---|---|---|---|
| `score.py train <파일>` | 누구나 | 무제한 | 전체 지표 + 연도별 IC |
| `score.py cv <파일>` | 누구나 | 무제한 | train을 2년 블록 4개로 나눈 IC·t·증분 IC, 양수 블록 수, train 지연 점검 |
| `score.py public <파일>` | 본인이 자기 id 파일로 | **id당 하루 3회** (KST, 자정 초기화) | public IC와 t |
| 최종 | `FINAL.txt`에 파일 이름 **최대 2개** | 마감까지 고치기 자유 | 마감 후 호스트가 한 번 채점, private 전체 |

- public 제출은 매번 시각·파일 해시와 함께 `LEADERBOARD.md`에 남습니다. public은 36개 날짜뿐이라 잡음이 큽니다.
  IC의 오차가 대략 ±0.03이라 그보다 작은 개선은 public으로는 보이지 않습니다. public 1등을 쫓아가면 과적합됩니다.
  **개선은 `cv`로 반복하고, public은 확인용으로 쓰세요.** 캐글의 "Trust your CV"와 같습니다.
- 최종 제출 파일은 마감 후 고치면 안 됩니다. 리더보드의 해시로 확인합니다.
- **참고 채점 (판정 없음).** 마감 후 공식 채점 때, 아래 파일도 같이 private까지 채점해 리더보드 "참고 채점" 표에 올립니다.
  - public에 낸 모든 버전. 제출 뒤 파일이 바뀌었으면 git 이력에서 해시가 같은 버전을 찾아 씁니다. 그러니 **제출한 버전은 커밋해 두세요.**
  - 마감 때 자기 폴더에 남아 있는 `predict()`가 든 `.py` 전부. train에서만 시험한 아이디어도 여기서 점수를 받습니다.

  최종 제출 2개는 공식 표에만 나옵니다. 참고 채점은 순위·판정에 들어가지 않습니다. 파일 수가 많아 t ≥ 2가 우연히도 나오므로,
  좋게 나온 아이디어는 다음 연구의 후보로만 씁니다(§10). 실행에 실패한 파일은 이유와 함께 목록에 남깁니다.
- 실행 명령은 레포 루트에서 `python competition/score.py ...`입니다.

## 8. 외부 데이터 (허용)

주어지지 않은 데이터도 쓸 수 있습니다. 일별 주가, 업종, 공시, 수급, 거시 지표, 뉴스 등. 조건은 아래와 같습니다.

1. **그 시점에 알 수 있었던 값만** 씁니다. 파일마다 "언제 알 수 있었는지" 열(예: `available_date`, 공시 접수일)을 두고,
   `predict()` 안에서 `available_date <= as_of`로 자릅니다. 분기 실적을 분기 말 날짜로 붙이는 식은 미래 정보입니다.
2. 파일은 `participants/<id>/external/`에 두거나, 받는 스크립트를 같이 넣습니다. 출처·받은 날짜·정의는 REPORT.md 2절에 적습니다.
3. **외부 데이터로 탐색할 때도 2014-01-01 이후 구간은 보지 않습니다.** 받아둔 파일에 숨긴 구간 값이 들어 있어도
   그 부분으로 그래프를 그리거나 통계를 내면 안 됩니다. 그 값은 `predict()`가 채점 중에 쓰는 것으로만 존재해야 합니다.
4. 호스트는 채점 전에 외부 파일과 코드를 읽어 시점 처리를 확인합니다. 미래 정보가 발견되면 그 제출은 실격입니다.

## 9. 금지와 정직 규칙

- **숨긴 데이터 `~/.quant-comp-private/`는 열지 않습니다.** `score.py` 안에서만 쓰입니다. 그 안의 `submissions.jsonl`(제출 기록)도 손대지 않습니다.
- `predict()`는 자기 폴더와 받은 인자 밖의 파일을 읽지 않습니다.
- **마감 전까지 다른 참가자의 폴더(`participants/<남의 id>/`)를 읽지 않습니다.** 캐글처럼 남의 코드는 볼 수 없는 것으로 칩니다.
  리더보드의 public 점수는 봐도 됩니다. `baseline/`과 `_template/`은 누구나 봅니다.
- 고치고 커밋하는 파일은 자기 폴더 안만입니다. `register.py`와 `score.py`가 고치는 `LEADERBOARD.md`는 예외입니다.
  네트워크 요청도 하지 않습니다(외부 데이터는 미리 받아 `external/`에).
- 숨긴 구간(2014-01-01 이후)의 주가 흐름을 보고 아이디어를 정하지 않습니다. 2020년 폭락 같은 상식 수준의 기억까지 막을 수는 없습니다.
  다만 "그 구간에 무엇이 올랐는지 찾아보고 맞추는" 것은 금지입니다.
- **시도한 것은 전부 REPORT.md 3절에 적습니다.** 지표 조합 20개를 train에서 돌려 하나를 고른 것과 처음부터 하나만 시험한 것은
  같은 t값이라도 믿을 수 있는 정도가 다릅니다. 발표 때 시도 횟수를 함께 봅니다.
- 사전 예상(REPORT.md 1절)은 train 점수를 보기 전에 씁니다.

**같은 컴퓨터라는 한계.** 모든 참가자가 같은 맥북, 같은 계정을 씁니다. 숨긴 파일은 레포 밖에 두어 실수로 열 일은 막았습니다
(Claude Code는 작업 폴더 밖을 읽을 때 승인을 묻습니다). 그래도 마음먹으면 읽을 수 있으니 결국 자율 규칙입니다.
탐색 기록은 각자 REPORT.md와 git 커밋 이력으로 남깁니다.
이 룰북을 만들며 숨긴 데이터를 다룬 Claude(이 세션)와 호스트는 결과표에 "준비 과정 참여"로 표시합니다.

**경연 결과는 실전 매매를 바꾸지 않습니다.** "새 정보" 판정을 받은 아이디어는 research/에 새 절로 사전 등록하고
2026-11 이후 실제 데이터로 전향 기록(§50·§57-F 방식)을 시작합니다. 실전 도입 여부는 그 기록을 보고 호스트가 결정합니다.

## 12. 에이전트에게 맡길 때 줄 지시문

```
quant-lab의 competition/RULES.md를 끝까지 읽고 경연에 참가해. id는 <id>로 `python competition/register.py <id>` 실행.
```
